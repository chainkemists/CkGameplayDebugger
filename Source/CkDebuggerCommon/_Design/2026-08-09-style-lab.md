# Style Lab — debugger-wide theming via selection axes (P1 of the Debugger UX campaign)

Design authored 2026-08-09 (Fable session). Pattern source: CliSeqStyles' two-layer theme model
(palette vs colorless style selection), ported to idiom — not code — per the campaign brief.

## The two layers

**Layer A — palette (already exists, reuse it).** `UCk_Style_UserSettings_UE`
(CkFoundation `CkEditorTools/Settings/CkStyleSettings.h`) is the role-named palette; `CkStyle::`
accessors are the only way UI reads it. P1 adds NO new palette system. Missing debugger roles are
added as new properties on that class opportunistically when P3 migrates hardcoded stragglers
(each straggler → an existing role, a new role, or an `OverlayOf`/dim derivation — never a new
hex literal at a use site).

**Layer B — style selection (new).** Colorless per-axis choices: WHICH shape/density/treatment,
never which color. Colors always resolve through Layer A roles at render time, so palette and
selection stay orthogonal (CliSeqStyles' core invariant).

## Layer B architecture

All in `CkDebuggerCommon` (Runtime — the overlay must link it):

- `Styles/CkDebuggerStyleSelection.h` (the module's existing `Styles/` folder — do NOT create a
  sibling `Style/`) — one `UENUM(BlueprintType) enum class ECkDebugAxis_*` per
  axis (uint8, explicit `Count` omitted — UE reflection owns labels/serialization; ini stores
  names, unknown name → property default, which gives clamp-and-default on load for free) and
  `USTRUCT FCkDebuggerStyleSelection` holding one property per axis.
- `Settings/CkDebuggerStyleSettings.h` — `UCLASS(config=EditorPerProjectUserSettings)`
  `UCkDebuggerStyleSettings : UDeveloperSettings`, Editor Preferences → Ck → "Debugger Style".
  Holds `FCkDebuggerStyleSelection Selection`, `int32 SchemaVersion` (bump on any axis
  add/remove/reorder; on load, older version ⇒ warn + keep parseable fields), and the
  active profile name. Static `Get()` mirrors `UCkDebuggerSettings::Get()`.
  - **Live apply:** widgets re-read via `Get()` inside attribute lambdas / paint — no invalidation
    web (CliSeqStyles' getter-indirection). For the few STRUCTURAL axes, the class exposes
    `Get_Revision() -> uint32` (transient counter bumped by `NotifyChanged()`, which the Lab and
    the settings panel's PostEditChangeProperty both call); panels compare a cached revision in
    their gated Tick and `RequestRebuild()` on change. This is the entire invalidation surface.
- `Styles/CkDebuggerAxes.h/.cpp` — the option→widget mapping: **one free function per axis with a
  switch** (`namespace ck::debug_axes`), palette passed implicitly via `CkStyle::` roles, plus
  **metric companions** and **layout predicates** queried before composing (CliSeqStyles rule:
  width/metric queries move in lock-step with render, spec-enforced):
  - render fns, e.g. `Make_Chip(Selection, Text, Tone) -> TSharedRef<SWidget>`
  - metrics, e.g. `Get_RowPadding(Selection) -> FMargin`, `Get_IconSize(Selection) -> float`
  - predicates, e.g. `Legend_IsVisible(Selection)`, `Values_UseAlignedColumns(Selection)`
- Muting/dim is a **composition path** (choose muted role colors when building), never an alpha
  overlay wrapped around styled children — Slate's `ColorAndOpacity` multiplies and washes out
  chip fills the same way ftxui's pre-paint rule did.

## Axis catalog v1 (SchemaVersion = 1)

Counts are the enum's option count; default first unless noted. Every axis names the surfaces it
drives so U3 has an exact wiring list.

| # | Axis | Options | Drives |
|---|---|---|---|
| 1 | ChipStyle | Tint (def) / Solid / Outline / TextOnly | inspector badge boxes, feature chips, overlay field chips |
| 2 | RowDensity | Comfortable (def) / Compact / Airy | row padding metric: tree rows, inspector rows, overlay card rows |
| 3 | EntityIdStyle | NameAndId (def) / CompactId / NameOnly / HashTintedChip | `SCkDebug_EntityRef` (all call sites; P4 prettify lands here) |
| 4 | BadgeStyle | Solid (def) / Hollow / CountOnly | count badges, fold badges |
| 5 | SeparatorWeight | Hairline (def) / None / Standard / Heavy | section separators in inspector + overlay card |
| 6 | FoldChipStyle | Chip (def) / Text / Minimal | tree fold/group chips |
| 7 | ValueAlignment | Left (def) / Right / AlignedColumns | inspector value column (P3's aligned-numeric rows read this) |
| 8 | ProviderChipStyle | Tint (def) / Solid / AbbrevOnly | overlay section provider chips |
| 9 | LegendMode | Deduped (def) / Off / PerSection | overlay legend strip (P0's dedup becomes the default option) |
| 10 | MergeCountDisplay | SuffixText (def) / CountBadge / Hidden | how a merged row's ×N renders. NOTE: whether merging HAPPENS stays `UCk_DebugOverlay_Settings::bMergeDuplicateRows` (project-level, model pass); this axis only styles the count |
| 11 | FlashOnChange | Off (def until P4 wires it) / Value / Row | inspector value-change flash (P4) |
| 12 | SectionHeaderStyle | Uppercase (def) / Mixed / Minimal | inspector + overlay section headers |
| 13 | IconSize | Medium (def, 16) / Small (12) / Large (20) | `SCkDebug_Icon` sites via metric |

Later phases ADD axes (P2 relay affordance style, P4 complexity dial…) — that is the point:
the Lab is the iteration vehicle; each new behavior ships with its axis.

## Curated profiles

`FCkDebuggerStyleProfile { Name, Blurb, Selection }`, static registry in `CkDebuggerAxes.cpp`:

- **Classic** — all defaults (== default-constructed selection; spec-enforced identity).
- **Dense** — Compact, CompactId, CountOnly badges, None separators, Small icons, Hidden ×N.
- **Presentation** — Airy, NameOnly, Solid chips, Standard separators, Large icons.
- **Minimal ink** — TextOnly chips, Hollow badges, Hairline, AbbrevOnly providers, Off legend.

Applying a profile copies its Selection into settings + saves; any manual axis change flips the
displayed profile to "Custom".

## Style Lab surface — new module `CkStyleLabDebugger` (UncookedOnly)

Follow `CkDebuggerCommon/CLAUDE.md` §"Creating a new debugger module" (7 steps) exactly, plus the
launcher contract (`CkDebuggerLauncher/CLAUDE.md`): descriptor after tab spawner, generation
token retained, unregister before spawner removal, **add the tab ID to
`CkDebuggerLauncherCatalog.spec.cpp`** (census is enforced), category **Tools**, icon from the
existing General SVG pool.

Content (single tab, `SCkDebug_WindowChrome`-wrapped):

- **Left: the sample** — ONE realistic worst-case mock document (CliSeqStyles rule: not a widget
  grid): a canned overlay focus card (sections, merged ×N row, legend, omission line), canned
  tree rows (named / NO NAME / probe / group / folded), canned inspector sections (Transform,
  Network, an attribute with meter-worthy data, a badge box) — all built from hand-authored
  models (the P0 spec files show the model-building idiom) and rendered through the SAME
  `ck::debug_axes` functions the real surfaces use. Canned = deterministic + PIE-independent.
- **Right: the controls** — always-visible axis list: one row per axis (name, current value
  label, ◀ ▶ cycle buttons — reuse `SCkDebug_NameDepthCycler`'s chrome pattern), profile
  dropdown with blurbs, reset-to-Classic. Every change: write settings, `SaveConfig()`,
  `NotifyChanged()` — the sample re-renders next paint, real debugger tabs follow live.
- No PIE data, no ECS handles, no EndPIE concerns (nothing cached) — but still honor the
  refresh gate and the WindowChrome/status-strip contract.

## Acceptance (from the brief)

User iterates axes in the Lab and the REAL debuggers follow live: flip RowDensity → open ECS
tree re-spaces; flip LegendMode → overlay legend responds next frame in PIE. `[EDITOR-VERIFY]`.

## Implementation task units (Opus 5)

- **U1 — foundation (blocks the rest):** selection enums + struct + settings class (+revision) +
  `ck::debug_axes` render/metric/predicate library + profiles + spec
  (`CkDebuggerCommon` or `CkEcsDebugger` test host): default-selection==Classic identity,
  profile registry integrity, metric/predicate totality over every enum value (switch
  exhaustiveness via spec loop), revision bumps on NotifyChanged.
- **U2 — the Lab module:** `CkStyleLabDebugger` skeleton + mock sample + axis HUD + profiles UI +
  launcher registration + catalog spec row.
- **U3 — wire the real surfaces:** ECS debugger (tree rows, inspector builder, EntityRef sites)
  + overlay card (chips, separators, legend gate, ×N display, provider chips, densities) read
  `ck::debug_axes` instead of their current fixed choices. Byte-identical rendering under
  Classic is the regression bar.

U2 ∥ U3 after U1 lands. Gate after each: toolbox `--build --test`, patterns `Debug` +
`DebuggerLauncher`; visual = `[EDITOR-VERIFY]`.
