# CkJoltBakeInspector

Editor-only launcher tool for read-only inspection of every mesh under Jolt's configured baked roots.

- `Analyze All` is the only full-inventory load path. It processes one row per Slate tick after explicit user input. The queue holds one `FCk_Jolt_ScopedGlobalInit` lease only while active; cancel, refresh, window destruction, and completion release it.
- Inventory collection is AssetRegistry-only. Row audits call `ck::jolt::cook::Analyze_MeshShape`; do not duplicate cooker freshness, winding, or failure logic in this module.
- The preview renders audit value triangles through `FCk_DebugScene_Target`: source is red on the left, normalized candidate cyan in the center, and available current cooked shape green on the right. Its informational labels use Common's click-passive `SafeAreaOverlay`, below the shared toolbar, and state capped previews or the shared cooked-preview reason (missing, stale/incompatible, corrupt, or non-tri-mesh). Tear it down before its preview world; the module's `OnEnginePreExit` reset is required.
- Baking is explicit and routes exclusively through `UCk_JoltCook_EditorSubsystem_UE`. Bulk baking admits only audited, non-failing `CookMissing`, `RebuildStale`, `RebuildCorrupt`, and `RebuildInsideOut` rows. Never submit `FixSource`, `DeleteOrphan`, or current rows.
- Never rebuild the list from Tick. All-mode rows use attributes; filtered modes refresh only when a classification changes membership.
- `JoltBakeInspector.ui.html/.css` owns the action lane, metric cards, stable splitters and selected-item details; `JoltBakeInspectorRow.ui.html/.css` owns ordinary virtualized row presentation. Retain the exact SearchBar, pane-hosted list and preview renderer as native mechanics ports. Use live CkStyle tokens, `ECk_Tone` and `ECk_Icon::Jolt`; do not add inspector-local brushes or clickable chips inside list rows.
- `JoltBakeInspectorLegend.ui.html/.css` owns the informational preview legend inside Common's click-passive `SafeAreaOverlay`. The source/normalized/cooked colors represent geometry identity, not severity. Legend release precedes preview target/world teardown.
- Compatible resource reload retains native ports and selection. Required-port rejection leaves the committed view intact. Invalid startup uses disjoint fallback hosts; recovery must detach those hosts before transferring the exact ports. Held fallback controls must stay inert after transfer or release.
- Module close and pre-exit explicitly call `Release_AuthoredPresentation`, including when another owner retains the window: cancel analysis and its Jolt lease, release owned input, revoke callbacks/views, clear the list item source and tear down the preview before detaching the host. Destruction alone is not the production lifecycle boundary.
- Focused Editor filter: `Ck.Jolt.Cook.Inspector` (six tests). The authored production fixtures exercise physical non-bake controls, reload/rejection, fallback recovery, held-widget inertness and public close/reopen/pre-exit during active unresolved analysis. They create no assets and invoke no bake/cook action; they do not establish real-asset baking, browser pixel parity, packaged loading or campaign-wide input/teardown acceptance.
