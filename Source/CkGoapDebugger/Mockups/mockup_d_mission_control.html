GOAP Mission Control

A designer-first debugger for the CkGoap planner. It answers, at a glance: what is this agent doing, and why? — then lets a designer interrogate every rejected alternative, rewind every replan, and test "what if" world states without touching gameplay code.

The mockup below is live: it runs a miniature regressive-A* planner over the real FEAR-gym action catalog, so every panel reacts truthfully.

Five questions, five regions

Every region exists to answer a question a designer actually asks — in this order of frequency. Engineering detail is opt-in (Nerd mode), never the default.

1 · "What is it doing?"

The chain breadcrumb + Plan panel. Status pill, current step marked NOW, sub-plans nested inline. Fallback steps get an amber flag instead of hiding behind a cost number.

2 · "Why not the thing I built?"

The Decision panel scores every candidate: in-plan, viable-but-costlier (with the exact Δ), blocked (with the unmet keys), fallback. Cross-tier notes explain what the top planner can and cannot see.

3 · "Why did it change its mind?"

The timeline records every replan with its trigger (which key flipped, coalescing, policy) and an old-plan → new-plan diff. Scrub to any moment; pause-on-event catches the frame live.

4 · "What does it believe?"

The World State panel: live values, per-key usage counts, override-layer stack. Sandbox mode pushes a DebugUI layer to test "what if" without touching gameplay — with a blast-radius warning when the WS is shared.

5 · "Is my catalog sane?"

Catalog Audit re-surfaces the framework's setup checks (fallback guarantee, cycles, invalid goal keys, key budget) plus derived lint: cross-tier reachability and dead effects.

Implementation notes

Almost everything renders from today's API. The debugger is a read-only consumer of the public getters plus a signal recorder (OnPlanComplete, OnActiveChainChanged, OnValueChanged, OnPlannerActivated). Only four small hooks are marked above: a search-trace/stats getter, an exact replan-cause tag, and an optional engine-side history ring.
Sandbox is the override stack, by design. The WS utils already anticipate a fixed DebugUI layer: reads are shadowed, the base store stays truthful, and popping the layer restores reality. The debugger must surface the blast radius — a shared World State means every subscribed planner replans under the sandbox.
Derived lint is cheap and designer-gold. Cross-tier reachability ("Flank can never be scheduled here"), dead effects, and the thrash meter (replans/min vs. the coalescing window) are pure functions over data the debugger already holds — no engine changes.
Concept mockup — no live game data. Built solely from the CkGoap public API surface and the FEAR-gym catalog (2026-07-18). The in-page planner is a faithful miniature: regressive A* over constraint sets, hierarchical via the promoted sub-planner, fallbacks at cost 999.
